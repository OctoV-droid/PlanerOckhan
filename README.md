# МАСТЕРСКАЯ v2.5 — задачи внутри проектов и ручной порядок

Веб-планер для GitHub Pages: проекты, задачи с подзадачами, контент-план социальных сетей, ВУЗ, календарь, активность. Работает на компьютере и мобильных устройствах как PWA.

## Новое в v2.5

### 1. Просмотр задач конкретного проекта

Раздел **«Проекты»** → нажать **«Открыть проект ↗»**. Открывается отдельная страница проекта, где видны:

- **В работе:** запланированные и текущие задачи этого проекта.
- **Выполнено:** только закрытые задачи этого проекта.
- Количество активных и завершённых задач, число связанных публикаций, процент выполнения основных задач.
- Для каждой задачи: статус, дедлайн, приоритет, количество выполненных подзадач.
- Галочка для изменения состояния; **«✎»** для редактирования без выхода из проекта; **«Открыть ↗»** для перехода к полной карточке задачи (с подзадачами) на вкладке «Задачи».
- **«+ Задача для проекта»** создаёт задачу, уже привязанную к открытому проекту.

После перехода к задаче показываются **все задачи**, включая выполненные, а нужная карточка подсвечивается и прокручивается в видимую область.

### 2. Ручная сортировка задач

Раздел **«Задачи»** → список «Сортировать задачи»:

- **Мой порядок** (по умолчанию). На компьютере перетаскивайте задачу за значок **⠿**. На телефоне используйте кнопки **↑** и **↓**.
- **По важности:** сначала важные, потом обычные и несрочные.
- **По сроку:** сначала задачи с ближайшей датой, без даты в конце.
- **По проектам.**
- **По состоянию.**

Перемещение сохраняется в локальных данных, JSON-копии и после перезагрузки браузера. Переключение в автоматическую сортировку **не уничтожает** ручной порядок: вернитесь к «Мой порядок», чтобы увидеть свою последовательность.

**Ограничения:** ручное перемещение доступно только при режиме «Мой порядок» и пустой строке поиска. При выбранном фильтре «Активные» либо «Выполненные» стрелки меняют местами только видимые задачи. Новая задача в ручном порядке появляется сверху. Дедлайны и статусы не меняются при сортировке.

### 3. Сохранено из v2.4

Подзадачи без собственных дедлайнов, графики активности, ручная запись времени, раздел «ВУЗ», публикации, календарь, иконка сайта, iPhone/iPad PWA. Формат данных предыдущих версий совместим.

## Как обновить существующий сайт через GitHub Desktop

1. **Обязательно сделайте резервную копию:** в текущем планере откройте «Настройки и копия» → «Скачать JSON-копию». **Нельзя загружать личную JSON-копию в публичный репозиторий GitHub.**
2. Скачайте и распакуйте ZIP из ChatGPT.
3. GitHub Desktop → выбрать репозиторий `PlanerOckhan` → **Repository → Show in Explorer**.
4. Скопируйте **файлы внутри архива** в **корень** репозитория с заменой (`index.html`, `app.js`, `style.css`, `sw.js` и т. д.). Не помещайте их внутрь дополнительной папки.
5. GitHub Desktop → вкладка Changes → **Commit to main** → **Push origin**.
6. Дождитесь обновления GitHub Pages и откройте прежний адрес: <https://octov-droid.github.io/PlanerOckhan/>.
7. Если видите старый интерфейс: на компьютере обновите страницу без кеша (`Ctrl + F5`). На iPhone откройте страницу в Safari при подключении к интернету, затем перезапустите ярлык. **Перед удалением установленной иконки PWA экспортируйте JSON из самой установленной версии**, так как её локальные данные могут исчезнуть.

## Хранение данных

Ключ `localStorage`: `atelier_planner_v1`. Новые возможности не очищают старые записи. Восстановление JSON заменяет текущие записи в этом браузере; перед импортом создайте копию. GitHub Pages размещает только код, личные задачи не отправляются в репозиторий.

**Важно:** между устройствами пока нет облачной синхронизации. Задачи на ПК и iPhone могут различаться, если не переносить их через JSON.

## Техническая проверка

- JavaScript прошёл `node --check`.
- Проверены обработчики и сохранение в изолированном JS-тесте: загрузка старого v2.4 JSON, открытие проекта, разделение статусов, правка задачи, переход к ней, ручной порядок через стрелки и перетаскивание, новые задачи сверху, сохранение данных.
- Автоматическое браузерное тестирование в текущей среде заблокировано политикой запуска браузера, поэтому **физические iOS Safari и drag-and-drop в настоящем браузере требуют проверки после установки**.

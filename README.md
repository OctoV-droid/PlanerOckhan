# МАСТЕРСКАЯ v2.9

Обновление личного веб-планера для GitHub Pages / PWA. Основано на версии 2.8. Приложение остаётся локальным: без облачной синхронизации, без серверной базы и без необходимости вводить пароли соцсетей.

## Что нового в v2.9

### ВУЗ: предмет → работа → шаги

1. Перейти **ВУЗ → Работы и долги**.
2. В **Сессии** создать период (например, `Зимняя 2026/27`), если его ещё нет.
3. Нажать **+ Предмет**. Ввести название, преподавателя, сессию, при необходимости общий срок, пометку «Долг» и примечания.
4. Внутри предмета нажать **+ Работа**, добавить `ЛР №1`, `ЛР №2`, `КР`, зачёт или любую другую работу. У каждой работы отдельный срок, приоритет, тип, статус и заметки.
5. Под работой в строке **Новый маленький шаг** последовательно добавить `Расчёт КР`, `Чертёж №1`, `Чертёж №2` и т. п. Нажать **+ Шаг** или Enter для добавления. Нажатие галочки закрывает только конкретный шаг. Шаг можно переименовать, снова открыть или удалить.
6. Галочка слева от заголовка работы переводит её в **«Зачтено / закрыто»**. Закрытие всех шагов **не меняет автоматически** статус самой работы: сдача и принятие преподавателем остаются отдельным действием. Статус можно менять селектором внизу работы.

Верхние фильтры: **по статусу работ**, **по предмету** и **по сессии**. При первом открытии раздела отображаются все работы, в том числе запланированные. Если выбрать «В работе» или «Запланировано», списки не смешиваются.

### Долги и сроки

- **Долг**: явно отмеченный долг у предмета или хотя бы одна незакрытая работа со статусом «Долг».
- **Просрочено без долга**: у ещё не закрытых работ либо у предмета истёк срок, но статус «Долг» вручную не установлен.
- **Без долга**: нет просроченных сроков и принудительно поставленного долга.
- **Все работы закрыты**: все работы предмета получили «Зачтено / закрыто».

Простое истечение срока **не переводит** работу в «Долг» автоматически.

### Совместимость и удаление

- Старые данные v2.8 содержали массив `academic` с текстовым `subject`. При чтении их группируют по сочетанию **название предмета + преподаватель + сессия** в отдельные `universitySubjects`. Для каждого старого предмета создаётся устойчивый идентификатор; старые работы, их статусы, сроки, события активности сохраняются. При первом сохранении обновлённая структура попадает в JSON хранилища.
- Новые данные хранятся в поле `universitySubjects`. Старое поле `academic` сохраняется ради совместимости с календарём, статистикой и журналом; записи теперь также имеют `subjectId` и массив `subtasks`.
- Переименование/изменение преподавателя или сессии обновляет привязанные работы.
- Если удалить предмет с работами, они **не уничтожаются**, а переносятся в отдельный предмет **«Без предмета»**. Подзадачи сохраняются.
- Если удалить сессию, предметы и работы не удаляются, с них снимается привязка к сессии.
- Отметки выполнения маленьких шагов записываются в `activityLog` как подзадачи; принятая работа учитывается как учебная работа. Изменение/снятие галочек также пишется в лог. Записи о выполнении доступны в разделе активности.

### Что НЕ добавлялось в этой версии

**Архивирование завершённых задач** и **автопубликация Telegram / Instagram / ВКонтакте** пока не реализованы. Это предмет обсуждения будущих версий, а не обещание действующих кнопок.

## Как обновить на GitHub Pages

1. **В старой версии 2.8** зайти в **Настройки и копия → Скачать JSON-копию**. Сохранить резервный JSON приватно, НЕ загружать его в публичный GitHub.
2. Распаковать `MASTERSKAYA_v2_9.zip` и скопировать **содержимое** каталога `MASTERSKAYA_v2_9` (не сам каталог) в **корень** текущего GitHub-репозитория планера.
3. Скопировать **все файлы**, особенно **новый `university.js`**, обновлённые `index.html`, `app.js`, `style.css`, `sw.js`. Иначе окно ВУЗ не сможет загрузиться.
4. Сделать Commit и Push в GitHub Desktop. После обновления GitHub Pages перезапустить приложение с иконки телефона либо обновить страницу в браузере. Версия кэша PWA изменена на `masterskaya-static-v2-9`.
5. Проверить старые предметы, работы и посещаемость. Создать пробный шаг и закрыть его. Если после обновления не отображаются данные или есть ошибки, сохранить JSON, не очищать хранилище браузера и использовать копию.

**Важно:** данные каждого устройства остаются в его `localStorage` под прежним ключом `atelier_planner_v1`; копия браузера `atelier_planner_v1_last_good` тоже сохраняется. Программа не синхронизирует записи между мобильной и десктопной версиями. Два приложения Safari и PWA на iPhone иногда используют разные локальные хранилища.

## Файлы и проверка

- `app.js`: интерфейс и обработчики действий.
- `university.js`: правила миграции, очистка шагов и вычисление статуса предмета.
- `storage.js`: проверка JSON, чтение, безопасная запись и резервная копия.
- `analytics.js`, `habits.js`: прежние модели статистики и привычек.
- `index.html`, `style.css`, `sw.js`, `pwa.js`, иконки, `site.webmanifest`: веб-интерфейс и PWA.
- `tests/smoke_v29.py`: автоматическая проверка интерфейса в Chromium и миграции данных.

Автоматические сценарии Chromium пройдены: создание сессии, предмета, работ и подзадач; отметки и отмены; редактирование; отдельное закрытие работы; категории статусов; фильтр сессий; долговой статус; сохранение/экспорт; удаление предмета без потери работ; миграция v2.8; адаптивные ширины 320, 375, 768, 1280 пикселей. Safari/iPhone и установленный PWA на физическом устройстве **не проверялись**.

Для запуска теста локально нужны Python, Playwright и Chromium. Например: `python tests/smoke_v29.py` (тест использует `chromium` по пути `/usr/bin/chromium`; на Windows путь к браузеру надо изменить или убрать аргумент `executable_path`).

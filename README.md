# МАСТЕРСКАЯ v2.8 — привычки, категории задач и безопасное хранение

Обновление статического планера (GitHub Pages / PWA). Эта версия построена на исходниках **v2.7** и сохраняет прежний ключ данных `atelier_planner_v1`: рабочие записи пользователя не включены в архив и не должны храниться в публичном репозитории.

## Новое в v2.8

### Привычки

- Самостоятельный раздел **«Привычки»**: создать привычку с названием, иконкой/эмодзи и цветом, изменить или удалить.
- В разделе **«Задачи»** сверху появилась компактная панель привычек на текущий день.
- Нажатие отмечает привычку **не более одного раза за местный календарный день**, повторное нажатие заблокировано и в интерфейсе, и в хранимых данных.
- В разделе привычек отображается текущая неделя (Пн–Вс) с числами, отметками и общим количеством отметок.
- Дата определяется по **локальным часам устройства**. Если на телефоне выставлены неправильное время, часовой пояс или дата, отметка попадёт на соответствующий неправильный день. Серверной проверки времени нет.

### Графики и цвета

- График выполненных действий использует цвета проектов для **основных задач**; **подзадачи** выделяются голубым, **ВУЗ** фиолетовым, публикации отдельным цветом, старые события без привязки показываются как «Другое / старые события».
- Любому **проекту**, **задаче** или **привычке** можно назначить произвольный цвет через стандартный выбор цвета. Для задачи свой цвет необязателен, по умолчанию она наследует цвет проекта. Индивидуальные цвета выполненных задач также видны на графике.
- График времени по направлениям строится **только по записанным рабочим сессиям**; если выбрана привязка к проекту, используется цвет этого проекта; записи по вузу, другим областям тоже разделены цветом.
- Под обоими графиками расположена сводка за выбранный период, в графике времени указаны минуты и часы **по каждому направлению**. Галочка задачи не создаёт вымышленного рабочего времени.
- Старые события `activityLog` без `projectId` нельзя автоматически восстановить по проектам, поэтому они относятся к категории «Другое».

### Чёткие статусы

- В разделе «Задачи» фильтры: **В работе**, **Запланировано**, **Выполненные**, **Все**. При открытии показаны **В работе**.
- В карточке задачи и карточке проекта есть быстрый переключатель статуса без входа в редактор.
- В открытом проекте три раздела: **В работе**, **Запланировано**, **Выполнено**. Счётчики на списке проектов тоже разделены.
- В разделе «ВУЗ → Работы и долги» **В работе** больше не включает запланированные. Появился отдельный фильтр **Запланировано**. Другие фильтры «Долги и просроченное», «Закрытые», «Все», «Экзамены» сохранены.
- При снятии отметки с завершённой задачи восстанавливается её предыдущий открытый статус («В работе» или «Запланировано»), если он известен.

### Защита данных

- Хранилище вынесено в `storage.js`. Запись в `localStorage` проверяется после сохранения. Если она не удалась, появляется **неисчезающее предупреждение**, а сообщение «Сохранено» **не показывается**. Нужные данные остаются в открытой вкладке для экспорта JSON.
- До перезаписи создаётся одна локальная резервная версия под ключом `atelier_planner_v1_last_good`. Это только **последняя исправная копия**, а не полноценное историческое версионирование. Она также хранится в браузере и может быть удалена при очистке его данных.
- Если основной JSON повреждён, отображается последняя исправная копия при наличии. **Запись блокируется**, пока пользователь явно не нажмёт «Восстановить локальную копию» или не импортирует JSON из файла. Можно скачать исходные повреждённые данные для ручной диагностики.
- Импорт JSON сохраняется на диск **до замены данных приложения в памяти**. Если запись невозможна, текущие данные не заменяются.
- Проверка дат формата `YYYY-MM-DD` отвергает невозможные календарные значения (например, 2026-02-30, 2026-04-31): в необязательных полях они очищаются, записи с обязательной корректной датой фильтруются.

### Поддерживаемая структура

- `index.html`: статическая страница и навигация.
- `style.css`: оформление, адаптивность.
- `storage.js`: загрузка, запись, резервирование и восстановление.
- `analytics.js`: классификация событий и рабочих сессий по цветовым категориям.
- `habits.js`: независимая модель привычек и защита от дублей.
- `app.js`: интерфейс, обработчики событий и другие существующие разделы.
- `sw.js`, `pwa.js`, `site.webmanifest`, иконки: PWA и офлайн-ресурсы.
- `tests/smoke_v28.py`: сценарии браузерной проверки (нужны Python/Playwright/Chromium).

Это **частичная модульная переработка**, а не полное разделение `app.js`: весь исторический интерфейс изначально монолитный и остаётся в `app.js`. Новые модели и функции хранения/статистики вынесены отдельно, чтобы следующие итерации не усложняли его ещё сильнее.

## Установка / обновление через GitHub Desktop

1. **Обязательно** на текущем планере v2.7 открыть «Настройки и копия» и выполнить **«Скачать JSON-копию»**. Отложить файл в надёжное приватное место. Не загружать JSON с личными данными в публичный репозиторий.
2. Распаковать архив `MASTERSKAYA_v2_8.zip`. Открыть в GitHub Desktop свой репозиторий планера, командой **Repository → Show in Explorer** открыть его папку.
3. Скопировать **содержимое папки** `MASTERSKAYA_v2_8` в **корень** репозитория с заменой. Важно: копировать **все** новые `.js`-файлы (`storage.js`, `analytics.js`, `habits.js`), а не только `app.js` и `index.html`.
4. В GitHub Desktop проверить список изменений, нажать **Commit to main**, потом **Push origin**.
5. Открыть GitHub Pages, дождаться обновления. При запуске с иконки iPhone закрыть приложение и открыть снова. Для перестраховки можно открыть адрес в Safari и обновить страницу. Ключ кэша обновлён до `masterskaya-static-v2-8`.
6. Проверить несколько старых задач/проектов/записей ВУЗа, создать тестовую привычку и проверить, что она остаётся после перезапуска. При необходимости воспользоваться импортом из JSON, но помните: он **заменяет** текущие записи.

## Совместимость и ограничения

- Поддерживается локальный JSON v2.7, данные остаются в `localStorage` с исходным ключом. Добавлены `habits`, `habitChecks`, цвет задач, сведения о проекте в новых событиях активности.
- GitHub Pages публикует **только файлы кода**. Личные данные остаются в `localStorage` каждого браузера. Синхронизации между браузерами/телефонами нет.
- Резервная копия **не переносится** на другое устройство автоматически. Рекомендуется периодически вручную экспортировать JSON.
- Автоматизированные сценарии в Chromium с изолированным хранилищем пройдены (21 проверка, включая импорт/экспорт, защиту от переполнения и несовместимого JSON, мобильные ширины 320–1280 px). **Safari/iOS, установленное PWA и service worker в живом HTTP-окружении здесь отдельно не проверялись**. На рабочем телефоне требуется самостоятельная проверка.

## Для следующего обновления

Не удалять и не менять без миграции ключи `atelier_planner_v1` и `atelier_planner_v1_last_good`. Не добавлять пользовательские JSON-бэкапы в Git. При каждом выпуске обновлять версии в `index.html` и `sw.js` и повторно выполнять smoke-тесты.

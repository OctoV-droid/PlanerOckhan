# МАСТЕРСКАЯ v2.9.3

**Основа:** v2.9.2. Выпуск: 28 октября 2026 года. Все пользовательские записи продолжают храниться **локально в браузере**, в ключе `atelier_planner_v1`. Новая версия не загружает пользовательские данные на GitHub или в облако.

## Что изменено

### ВУЗ: ручной порядок

- Можно переставлять **предметы** и **работы внутри предметов**. Долги двигаются наравне с остальными работами.
- На ПК перетаскивай за знак **⠿**. На телефоне используй стрелки **↑ ↓**, так как HTML-перетаскивание на сенсорных устройствах ненадёжно.
- Порядок сохраняется в текущих массивах `universitySubjects` и `academic` через уже существующий механизм сохранения. Новых полей у предметов и работ нет.
- Работа не переносится в другой предмет случайным перетаскиванием. Для смены предмета используй редактирование работы.
- При фильтрах стрелки меняют порядок только среди видимых работ. После очистки фильтров полный порядок сохраняется.
- Сворачивания, подзадачи, статусы, сроки и отметки сдачи работают как раньше.

### Календарь

- На **телефоне и ПК** показывается полноценная сетка из 7 дней недели и 6 календарных строк.
- Цветные точки в дне показывают запланированные публикации, задачи, работы ВУЗа и занятия.
- Нажатие на дату открывает ниже **список событий только этого дня**. Кнопки «←», «Сегодня», «→» перелистывают месяцы.
- Даже пустые дни доступны для выбора, без огромного списка всех событий месяца.

### Активность

- Появилась панель **«Активность по дням»**: выбор любой даты до сегодняшней, стрелки для соседних дней, завершённые действия, отменённые отметки, записанное время, списки конкретных событий и рабочих сессий.
- На графиках теперь есть **подписанные шкалы значений**, подписи над частью столбцов, всплывающая подсказка и переход к выбранной дате при нажатии на столбец.
- На маленьких экранах графики прокручиваются **внутри собственных панелей по горизонтали**, не растягивая страницу.
- Помни: **сделанные галочки** считаются действиями, **потраченное время** считается только по добавленным рабочим сессиям. Они не взаимозаменяемы.

### Проекты

- Компактные карточки-«плитки» в несколько столбцов (на большинстве телефонов две, на ПК больше) с цветом проекта, процентом выполнения, краткими счётчиками и быстрым открытием.
- Сортировка: **мой порядок**, **больше выполнено**, **процент готовности**, **больше в работе**, **по названию**. Выбор сортировки сохраняется в данных как поле `projectSort`, совместимое со старыми JSON-копиями.
- Полная карточка проекта и работа с задачами в ней сохранены.

## Обновление GitHub Pages

1. В **текущем работающем** планере открой «Настройки и копия» и нажми **«Скачать JSON-копию»**. Сохрани файл отдельно. **Не добавляй JSON-файл с личными данными в публичный репозиторий GitHub.**
2. Распакуй `MASTERSKAYA_v2_9_3.zip`.
3. Скопируй **все файлы из папки `MASTERSKAYA_v2_9_3`**, кроме папки `tests` и файлов предварительного просмотра, **в корень существующего репозитория** с заменой. Обязательно обнови `app.js`, `style.css`, `index.html`, `sw.js` вместе.
4. В GitHub Desktop сделай `Commit to main` и `Push origin`.
5. После публикации открой планер на телефоне с интернетом; обнови вкладку/перезапусти PWA. Внизу страницы должна быть версия **v2.9.3**. Если старая версия осталась, закрой все вкладки приложения и открой сайт повторно; **не очищай данные сайта**.
6. Убедись, что все прежние задачи, предметы, привычки и сессии присутствуют. Если они пропали, ничего не создавай и не сохраняй в пустом планере до проверки хранилища и резервной копии.

## По вопросу об удалении выполненных задач

Функция архивирования **не реализована в v2.9.3**, как и просили.

- Самый простой способ: в разделе «Задачи» показывать только «В работе», тогда завершённые задачи скрыты, но не удалены, и статистика проектов остаётся прежней.
- Для настоящей очистки нужен архив: поле `archivedAt`/`archived` у задачи, скрытие её из рабочих списков, но сохранение записи, проекта, подзадач и событий активности. Тогда выполненные задачи перестают мешать, а история и процент выполнения проекта остаются корректными.
- Простое **удаление** задачи хоть и может оставить часть старых событий в `activityLog`, но **исказит текущие показатели проектов**, которые вычисляются по массиву задач. Поэтому для следующей версии лучше архивировать, а не удалять.
